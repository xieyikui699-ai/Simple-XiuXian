## 背景与定位

在主仓现网《掌门，不好了》之外，做一个微信小程序简化版：纯单机、文字经营修仙，两宗对抗。核心资产复用策略：不裁剪主仓 `packages/core`，而是新建本仓 `packages/engine`，从现网拷贝骨架后重写：

| 直接拷贝复用 | 照骨架新写 | 完全不带走 |
| --- | --- | --- |
| `battle.ts` 1v1 回合框架、`attributes.ts` 正态生成、`naming.ts` 取名、sha256 种子哈希体系、effects 分来源聚合模式 | 境界表、宗门规则、灵石经济、月结引擎、NPC 宗门运行时、全部内容目录 | `db`（SQLite→本地存储）、`task-center`（→UI 定时器）、server、market/world/sect-library/legacy/calamity/relationships |

## 已确认决策（用户拍板）

1. **胜负条件：混合**——我方弟子先圆满元婴前期飞升获胜，或压制对方宗门实现吞并获胜。
2. **资源：只留灵石**——灵脉/药园/灵木/材料全部去掉，丹药、升阶、招募、维护只耗灵石。
3. **结局：元婴前期圆满=飞升结局**——触发结算评价，可开新局；元婴中后期只留数据扩展位不实装。

## 灵石经济

- 初始灵石 2,000、士气 70、声望 50。
- 月入：外门供奉 = 外门人数 × 2；经营方针额外 +外门人数 × 1。
- 月支：内门俸禄 10/人/月；招募 300/人（候选 3 选 1，入外门）；方针消耗（闭关 15/月、历练 15/月）。
- 资源危机：灵石 + 收入 − 俸禄 − 方针消耗 < 0 时，方针未执行、成本勾销、士气 −3、warning 纪事。
- 士气 0–100：≥70 真元 +10%、≤30 真元 −10%；来源：休养 +5/月、闭关/经营 +1/月、历练 −2/月、会战胜 +5 / 败 −5、切磋胜 +1 / 败 −1、每坐化 −5、危机 −3。

月度方针 4 选 1：闭关修炼（真元 +30%）、外出历练（触发历练事件）、经营宗门（灵石 +）、休养生息（士气恢复、伤势加速恢复）。

## 弟子

- **五行灵根**：类型决定真元倍率（五行杂 ×1 / 四 ×1.5 / 三 ×2 / 双 ×3 / 天灵根 ×5），分布 40/30/18/10/2%；元素列表（金木水火土）决定法术相性。
- **五维**：力量/魂力/身法/体魄/悟性，截断正态生成（均值 50、σ20、值域 [10,90]）；有效值 = clamp(1, 100, 基础 + 天赋平加 + 功法平加 + 装备平加)。
- **天赋**：每人 1–3 条（50/35/15%），目录 30 条无品级，权重抽取不重复。
- 忠诚度、结缘、师徒、道侣、血脉代际全部不做。

## 战斗系统（1v1 回合制）

**属性派生**（唯一公式 owner，玩家与 NPC 共用）：

| 派生值 | 公式 |
| --- | --- |
| 最大生命 | 100 + 体魄 × 5 + (实力等级 − 1) × 50 |
| 物理攻击 | 力量 × 2 + 武器攻击 |
| 法术威力（法威） | 魂力 × 2 + 法宝法威 |
| 防御 | 体魄 × 1.5 + 护甲防御（向下取整） |
| 先攻 | 身法 + 天赋先攻 + 减速修正 |

**回合规则**：先攻高者先行动（同值攻方先）；每回合可选择普通攻伐（物理，1.0× 攻击）或一门无 CD 法术；伤害 = max(1, round(攻击力 × 倍率 − 防御 × 0.8))；命中率 90% 固定；暴击率 5 + 天赋暴击（上限 50），暴伤 1.5×；先手打出致命一击即结束，最多 30 回合，未分胜负判平（双方无伤势，切磋记平局）。

**状态效果**（同状态不可叠加，异源刷新取最强）：灼烧（行动后每回合扣 6%/8% 最大生命，3/2 回合）、冰冻（下回合无法行动）、减速（先攻 −5，3 回合）、护盾（吸收伤害直至破除）、反伤（受击反弹 10%）；状态抗性（百毒不侵 20%）按概率抵消状态附加。

**伤势**：战败方 40% 轻伤（禁出战 1 月）、20% 重伤（禁出战 3 月），其余无伤；休养方针下所有伤势恢复月数 −2；战斗胜利无伤势。

## NPC 对手宗门

**构成**：开局与玩家同为 1 级宗门：掌门 1 + 内门 3 + 外门 20，弟子用同一生成器（灵根/五维/天赋/寿命）。装备按宗门等级自动配最强档（1 级→档 1、2 级→档 2、3 级→档 3），不服用丹药。

**月度运行时**（确定性，与玩家月结同帧推进）：内门弟子真元/突破（同一公式）；每月招募 1 名外门（灵石充足时）；满足升阶条件自动升阶；培养焦点随机但不重复倾向（影响招募候选五维偏向）。

**难度三档**：发展速度 ×0.8 / ×1.0 / ×1.2（作用于 NPC 月度真元收益与招募频率），开局选定。

**情报透明**：对方宗门等级、灵石区间、弟子名册（姓名/境界等级/实力等级/伤势）常驻可见。

## 两宗对抗

- **相遇**：玩家历练切磋/掠夺事件的对家即 NPC 宗门弟子（见历练事件表）。
- **宣战**：玩家可随时宣战（无前置条件）；NPC 在「声望差 >50 或其宗门等级更高」时每月 15% 概率宣战。宣战后进入战争状态直至会战结算，之后 12 个月冷却。
- **会战**：宣战次月触发。双方各派 3 名可出战内门弟子（玩家可指定，默认自动选最强 3；不足 3 人按实有数），按实力等级降序（同值真元高者优先）同序配对，逐场 1v1，**胜场多者赢**（1:1:1 平局时总伤害高者胜，仍平判玩家胜）。
- **会战结果**：胜方掠夺败方灵石 10%（上限 5,000）+ 声望 +10 + 士气 +5；败方声望 −10 + 士气 −5；参战者按战败伤势规则结算；每场战报可回放。
- **声望**：来源见历练/会战；大境界突破（进入 4/7/10 级）+3；无月度消退。声望下限 0。

## 胜负与结局评价

- **飞升胜利**：我方任意弟子元婴前期圆满突破成功。
- **吞并胜利**：对方声望 ≤0 且我方宗门等级 > 对方 → 次月结算触发。
- **失局**（对称判定）：我方声望 ≤0 且对方宗门等级 > 我方 → 被吞并；内门弟子为 0 且灵石不足招募费连续 6 月 → 宗门凋敝。
- **结局评价**：用时（游戏年）、突破总次数、会战胜绩（胜/总）、坐化弟子数、剩余灵石 → 综合评分给「仙途评级」（甲/乙/丙/丁四档），可开新局。

## 月结流程（顺序）

1. 灵石结转（供奉/俸禄/危机判定）
2. 方针效果（闭关/经营/历练/休养）
3. 弟子真元增长与突破判定（含飞升检查）
4. 丹房/器坊点数与出炉
5. 历练与遭遇事件（方针=历练时）
6. NPC 宗门推进
7. 会战结算（若到期）
8. 声望/士气落地、胜负判定（吞并/失局）
9. 第 12 月：年度衰老与坐化

## 工程方案

- **`packages/engine`**：确定性规则引擎，纯 TypeScript、零 Node 依赖（sha256 自实现），node 里跑切片测试，与 UI 解耦。M1 已落地：hash/realms/attributes/roots/lifespan/talents/naming/generation/sect/settlement/engine + 39 项测试。
- **sha256 自实现**：DataView 大端读写，测试文件内用 `node:crypto` 对拍验证。
- **`apps/miniapp`（M4）**：UI 框架默认 **Taro（React）**（组件化 + 未来多端），如实施时改选原生 WXML 需先修订本设计。快照 JSON 存 `wx.setStorage`（预计 <100KB），手动 3 格 + 自动 1 格（key：`simple-xiuxian-save-1..4`）；自动推进 = UI 层定时器 1 秒 1 月。
- 主仓现网代码、测试、玩法不受影响。
